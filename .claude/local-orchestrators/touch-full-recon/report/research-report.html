What blocks

The ten blockers

Each one either poisons the next implementation step or falsifies a decision the prior plans rely on. All ten are resolved by name in the new plan.

PRODUCT-2 · AUDIT-14 · RUNSTATE-10

.touch/ is not gitignored in a repo with zero commits — and that store is specified to hold unredacted transcript content. Any git add -A after the first code lands would bake secrets into commit #1. The plan makes the gitignore edit the hard precondition for everything else (R-01, GD-1).

PLANS-1

Two rival plans both claim to be consumable by implement-plan as-is, with colliding file ownership and no supersession statement. The new plan supersedes both explicitly and maps every old item id to its replacement.

SKILLS-1

A fully green implement-plan run reports “run failed”: any plan whose agents return no pass/approve verdict — every research fan-out, every divide phase — closes red. Verified against real history and in simulation; the repo’s flagship successful run is on record as a failure (R-08/R-09).

MONITORING-2

The monitor server binds 0.0.0.0 with no auth and accepts cross-origin WebSocket upgrades (verified live). Tolerable for a read-only dashboard; disqualifying for a product with terminate buttons. Touch gets a decided posture before any control endpoint exists (GD-13).

PLANS-2

The v0 plan ships stop controls for sessions the design law defines as read-only, and the touch-orchestrate skill quietly introduces a third session class no decision admits. Resolved as three explicit classes with evidence-gated promotion (GD-6).

RUNSTATE-2

Legacy event streams carry no run id or task id, and one folder’s stream spans two script invocations — the planned ref union cannot represent them. A dedicated legacy adapter with synthesized refs is now its own plan item (R-27, GD-14).

AUDIT-1

The 51 findings from the earlier aborted recon run have zero disposition in any plan — both plans predate them. A findings-disposition register with a static completeness test closes the loop (R-06, GD-17).

AUDIT-2

The design law’s “journal result is an opaque string, never parsed” is falsified by every journal on disk — and contradicts the verdict mapper the plan itself reuses. Amended: result is polymorphic (GD-11).

AUDIT-3 · PLANS-8

The entire v0 stop story rests on hook hot-reload behavior nobody has probed. The control phase is now gated on a ten-minute experiment (R-04) instead of an assumption (GD-19).

PRODUCT-1

CLAUDE.md — the file every fresh session auto-loads — carries a false repo inventory and points at neither inception.md nor either plan, so the next implementer would re-derive a design that ~1.1M tokens of research already settled. Fixed by the docs truth pass (R-05).

What got decided

Twenty global decisions — the load-bearing eight

  • GD-1/2

    Repo safety first: no commit until the gitignore is hardened and git identity exists; branch renamed to main; two commits — tooling+docs, then orchestration history, taken only while no watcher is writing.

  • GD-4

    One vocabulary for control verbs. “Restart” gets its single meaning: re-invoke the workflow script with the stored partition and only:[ids] — fresh agents, attempt numbering continues. resumeFromRunId is rejected as a restart (it replays without re-executing). Pause stays deferred and is never rendered where it can’t be honest.

  • GD-5

    The user-directed model table, rescued from the aborted run and now recorded durably: Opus @ xhigh for research/implement/gate/critique; Fable for synthesizer, divider (explicitly closed), main terminal, final review.

  • GD-6/7

    Three session classes — owned, cooperating, observed — with evidence-gated promotion; and harness-first node identity: harness facts create graph nodes, markers only label them. A missing marker degrades the label, never the node.

  • GD-8

    Two run profiles, honestly: Workflow runs (journal-sourced, stop unavailable and shown as such) and Agent-tool runs (spawn ledger + TaskStop works). The journal stops being the only event source.

  • GD-10

    Plan-close semantics that stop recording green runs as failures: research-shaped plans settle “done” or “closed — no verdict”, templates must emit terminal events, and “no complete event + quiet journal” renders as unknown, never running.

  • GD-13

    Security posture decided before any control endpoint exists: 127.0.0.1 by default, per-boot 256-bit token on every route, Origin/Host allowlist enforced at WebSocket upgrade, read-only and control route groups separated.

  • GD-14

    A full legacy-ingest rule set: synthesized refs for the historic streams, re-labels marked derived_from_legacy, fabricated “failed” verdicts corrected at read time, and .watcher-state.json declared watcher-private — Touch never reads it.

One inter-report contradiction was settled empirically during synthesis: git stash create on this zero-commit repo exits 1 with no sha — AUDIT-8 was right, PLANS-9’s exit-0 claim is corrected in the plan’s discard register.

The road

37 items in five gated phases

  1. Repo safety, fixtures, truth

    R-01 … R-06

    Harden .gitignore before anything creates .touch/; git bootstrap to main; freeze the wf_829e6f58 fixture corpus before the CLI retention sweep deletes it; run the five settling probes; the docs truth pass; the findings-disposition register.

    gate: nothing else may start first

  2. Monitoring-module fixes

    R-07 … R-17

    Watcher crash-safety and truncation handling; honest plan-close/run-close semantics; terminal events from the templates; write integrity (flock, detail caps); server 404-not-fallback and Origin allowlist; dashboard scalability; full-length agent ids; real tests replacing tautological ones.

  3. Protocol: topology, restart, touch-orchestrate

    R-18 … R-21

    One marker grammar emitted correctly at the source; durable topology.json + re-entry args that make restart real; touch-orchestrate rewritten around the two run profiles with a conformance test; the role→model table applied.

  4. Touch v0 — monitoring only

    R-22 … R-33

    The aggregator (tailer, store, sessions, ingest, legacy adapter, agents, ws, server, read API) and the read-only touch-visual frontend. Zero control verbs render in this phase.

  5. Control plane

    R-34 … R-37

    Session classes and addressable control files; the stop verb with a three-state checkpoint; the hook pack in whichever delivery mode the probe validated; end-to-end simulation with per-phase acceptance against fixtures.

    gate: blocked on the R-04 probe results

Supersession

What happened to the prior plans

Both prior plans are now historical records: touch-aggregator-plan.md (T1–T23) and touch-monitor-spawn-plan.md (P1–P12) must not be handed to implement-plan again. The design decisions D1–D14 remain law except where amended: D1 (session classes), D3 (identity), D4 (ref union), D5 (state layout), D7 (verbs) are amended; D8’s opaque-result rule is superseded; D2, D6, D9–D14 stand. Every old item id maps to its successor in the plan’s §0 table, and deliberately deferred items keep their original ids so nothing is silently lost.
