The Touch mirror, collection by collection

Touch mirrors what it reads from ~/.claude and .touch/ into MongoDB so history survives the CLI's own rewrites. The schema is defined in code — the COLLECTIONS table in aggregator/mongo_store.py — and installed by ensure_schema on first mirror boot: a $jsonSchema validator and the declared indexes per collection, nothing else. Fifteen collections; every _id is a string built by refs.ref_key, never a sub-document.

The update algebra (GD-25)

every write goes through bulk_upsert or guarded_update; no mapper holds a raw collection handle

Allowed — replay-idempotent by construction

  • $max / $minaccumulation as absolute values — normal, shuffled, reversed ingest all fingerprint identically
  • $addToSetmulti-valued fields as sets, BSON equality (field order matters in sub-documents)
  • $setOnInsertimmutables, written only by whichever op creates the doc — every op on an _id must carry the same payload
  • $setfenced: the only way to write gen and retracted; refused on any accumulable field

Forbidden — named, with reasons

  • $incre-ingest after a transcript rewrite is mandatory; summed deltas double
  • $pushnot idempotent under replay
  • $pull / $pop / $unsetthe mirror is upsert-only; disappearance is a field, never a removal (GD-26)
  • $renamekeys are the schema; a write-time rename hides a mapper bug
  • $currentDatethe aggregator supplies every ts; the server never invents one (GD-11(g))
  • $bitnot part of the algebra

Structural invariants — enforced by the server, not the review

  • Every _id is a string from refs.ref_key — the $jsonSchema validator pins _id: {bsonType:"string"}, so a sub-document key (field-order sensitive, inserts as two docs) fails at write time.
  • No TTL index anywhere, ever — index_def raises on expireAfterSeconds, and ensure_schema reads the server's indexes back and refuses to start if one appeared by hand (GD-26).
  • Upsert-only, with two scoped exceptions — the DB role grants remove only on stream_meta (positional renumber) and dropCollection only on derived (reducer rebuild). A stray deleteMany fails at the server.
  • Oversize ⇒ stub, never a silent drop — above 8 MB (BSON cap 16 MiB) a document keeps its _id, key fields, provenance, ts plus {oversize:true, bytes}, so it still joins, sorts and counts (R-44).
  • Hostile keys ride in _raw wrappers — dotted / $-prefixed keys (file paths, tool inputs) are stored as {_raw:"<json>", _rawEncoding:"json", _rawKeys:n}; undeclared ones get auto-wrapped and marked _rawAuto.
  • Secrets never land — deny-listed files are never read; on the way out of the queue, values under names matching (?i)(token|secret|key|password|auth) become [redacted], with declared schema fields and validated ref{}s exempt.
  • Client timeouts are contract — serverSelectionTimeoutMS:500, connectTimeoutMS:500, socketTimeoutMS:2000: a dead mongod costs one 500 ms probe, then a 30 s circuit-breaker hold, never pymongo's default 30 s stall.
