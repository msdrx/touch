// recovery

Network-failure & restart strategy

Everything monitored is local — sandbox, daemons, dashboard, events.jsonl, the workflow journal. An uplink drop only threatens in-flight agent API calls. Three failure layers, each with its own answer:

1

Transient drop — seconds to minutes

Harness retries the API call with backoff. No action. Post-hoc signature: repeated attempt N spawned, a from-zero token tick, or unmoved cache-read with jumped cache-write. Both of today's incidents lived here.

2

Agent death — outage outlasts harness retries

agent() returns null; an unguarded loop burns a gated attempt. Every spawn now goes through agentR(): retry the same work up to 3× on the same attempt, then throw — stopping cleanly beats grinding through attempts. A thrown run is the expected outcome of a long outage; it resumes with zero lost work.

3

Driver or session death

All completed work persists in the journal and the working tree. Restart manually with the procedures below.

const agentR = async (prompt, opts) => {
  let r = await agent(prompt, opts)
  for (let n = 1; r === null && n <= NET_RETRIES; n++) {
    log(`${opts.label}: agent returned null (network drop?) — retry ${n}/${NET_RETRIES}`)
    r = await agent(prompt + `\n(infrastructure retry ${n}: previous try died — network
        outage, not a task failure. Do the task from scratch.)`,
      { ...opts, label: `${opts.label}~r${n}` })   // distinct prompt ⇒ resume re-runs it live
  }
  if (r === null) throw new Error(`${opts.label}: died ${NET_RETRIES+1}x — resume per RESUME.md`)
  return r
}

Manual restart procedures

  1. Same session still alive

    Stop the stale task, relaunch with Workflow({ scriptPath, resumeFromRunId, args }). Completed agents replay instantly from the journal cache; execution resumes live exactly at the interrupted loop. Never reword earlier prompts before a resume.

  2. New session (journal cache doesn't apply)

    Don't relaunch blindly — the tree holds completed loops' work. List green loops from the journal and event cards, filter them out of the sub-plans array in a script copy, launch fresh. Idempotent gates converge the half-finished loop on attempt 1.

  3. Restart one loop only

    Run a focused remediation loop: fresh implementer briefed with the loop's open findings/ files, same read-only gate and critique, same caps. Findings files are the complete handoff by design.

  4. Daemons

    One watcher per task, pointed at the new wf_dir; update orch-config.json. Monitor server serves all tasks — no restart. Never delete events.jsonl or .watcher-state.json during recovery.

  5. Run completed while offline

    The journal's last record holds the return value: close open cards, emit orchestrator complete done, build and publish the final report.
